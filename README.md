# txta.dev CLI

Send an encrypted letter to a developer's GitHub profile repository from your own machine and GitHub account.

```bash
npx txtadev
```

The canonical package is also directly runnable:

```bash
npx @txtadev/cli
```

The CLI asks for a GitHub username, discovers the recipient's published SSH encryption keys, prompts for the letter, encrypts it locally, and creates one immutable issue in the recipient-owned `username/username` profile repository through your authenticated [`gh`](https://cli.github.com/) session.

## Requirements

- Node.js 22 or newer
- GitHub CLI authenticated as the sender: `gh auth login`
- The recipient publishes an `ssh-ed25519` or `ssh-rsa` key and has Issues enabled on their public profile repository

## Non-interactive handoff from txta.dev

The command generated by [txta.dev](https://txta.dev) passes the draft over standard input, where the CLI encrypts it before GitHub receives anything:

```bash
npx txtadev --to octocat --fingerprint SHA256:... --yes <<'TXTA_LETTER'
Your private message
TXTA_LETTER
```

`--fingerprint` is a rotation guard: the CLI refuses to send if the selected public key changed after the browser checked it.

## What receives the message

txta posts one issue titled `📬 You've got mail` to `recipient/recipient`. The issue contains the frozen txta.dev letter renderer and one AGE envelope. The recipient decrypts with stock `age`; txta.dev has no backend in the sending path and never receives the draft, ciphertext, or GitHub credential.

## Package structure

- `@txtadev/cli` owns all implementation.
- `txtadev` is a minimal forwarder pinned to the exact same version.
- Changesets keeps both packages in one fixed release group, and `scripts/check-lockstep.mjs` rejects version or dependency drift.

Publication runs only through the protected GitHub Actions release workflow.
